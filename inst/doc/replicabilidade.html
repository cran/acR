Esta vignette demonstra o pipeline completo de análise de conteúdo qualitativa assistida por LLM, com foco na replicabilidade: cada decisão metodológica é documentada de forma que outro pesquisador possa reproduzir a análise apenas com o codebook em YAML e o relatório gerado por ac_qual_report().

A demonstração usa dados sintéticos (ac_qual_code() requer chave de LLM paga); a estrutura, formatos e sequência são idênticos a uma rodada real.

O pipeline em 6 etapas

  1. Coleta: corpus real ou fabricado
  2. Codebook: instrumento analítico (ac_qual_codebook)
  3. Classificação: LLM com live view (ac_qual_code(live = ...))
  4. Amostragem para revisão: ac_qual_sample()
  5. Confiabilidade inter-codificador: ac_qual_reliability()
  6. Relatório de método: ac_qual_report()

2. Codebook

O codebook é o instrumento central. Aqui usamos três categorias (favor, contra, neutro/técnico) com definições operacionais e exemplos positivos e negativos para desambiguar categorias vizinhas.

cb <- ac_qual_codebook(
  name         = "posicao_reforma_tributaria",
  instructions = paste(
    "Classifique a posicao do parlamentar sobre a reforma tributária",
    "com base no discurso apresentado."
  ),
  categories = list(
    favor = list(
      definition   = "Apoio explicito a aprovacao da reforma tributária.",
      examples_pos = c("Sou a favor desta reforma que simplifica o sistema."),
      examples_neg = c("O texto altera o artigo 145 da Constituicao Federal."),
      weight       = 1
    ),
    contra = list(
      definition   = "Oposicao explicita a reforma, com argumentos de rejeicao.",
      examples_pos = c("Voto contra: prejudica os trabalhadores."),
      examples_neg = c("Precisa de ajustes antes da votacao."),
      weight       = 1.2  # categoria com mais dificuldade retorica
    ),
    neutro = list(
      definition   = "Discurso técnico ou processual, sem posicionamento claro.",
      examples_pos = c("O relatório incorporou emendas apresentadas."),
      examples_neg = c("Sou totalmente contra esta proposta.")
    )
  ),
  lang = "pt"
)

3. Classificação com live view

Em uma rodada real, o comando seria:

library(ellmer)
chat <- chat_anthropic(model = "claude-sonnet-4-5")

resultado <- ac_qual_code(
  corpus        = corpus,
  codebook      = cb,
  chat          = chat,
  k_consistency = 3,           # 3 rodadas de self-consistency
  reasoning     = TRUE,        # pede raciocinio estruturado
  live          = "terminal"   # ver o LLM classificando ao vivo
)

Com live = "terminal", cada documento aparece na hora:

4. Amostra para revisão humana

Para estimar a confiabilidade que vai para o artigo, a amostra precisa ser representativa do corpus (Krippendorff, 2018, cap. 12): use strategy = "random" (padrão) ou "proportional". A estratégia "uncertainty", que prioriza documentos com menor confidence_score, é útil para outra coisa: diagnosticar erros e refinar o codebook. A concordância calculada nela não representa o corpus, porque a amostra foi escolhida justamente entre os casos difíceis.

amostra <- ac_qual_sample(
  resultado,
  n        = 4,
  strategy = "random"
)
#> ℹ Amostra de 4 documentos selecionada (estratégia: "random").
#> ℹ Use `ac_qual_export_for_review()` para exportar para Excel.
amostra |> dplyr::select(doc_id, categoria, confidence_score, sample_reason)
#> # A tibble: 4 × 4
#>   doc_id categoria confidence_score sample_reason

#> 1 d01    favor                    1 random       
#> 2 d05    contra                   1 random       
#> 3 d12    neutro                   1 random       
#> 4 d09    neutro                   1 random

Em uma rodada real, você exportaria essa amostra para Excel, um codificador humano preencheria a coluna categoria_humano, e o resultado seria reimportado:

ac_qual_export_for_review(amostra, path = "revisao.xlsx", corpus = corpus)
# ... revisor humano preenche a coluna categoria_humano no Excel ...
revisado <- ac_qual_import_human("revisao.xlsx")

Como ler esta tabela

  1. Onde olhar. Uma linha por métrica. Leia três colunas juntas: estimate (o valor), ci_lower e ci_upper (o intervalo de confiança: onde o valor verdadeiro provavelmente está) e interpretation (o rótulo, segundo a referência própria de cada métrica).

  2. O que este exemplo mostra. Com 1 discordância em 12 documentos, o percent agreement é ≈ 0,92. As métricas que descontam o acaso ficam um pouco abaixo: alfa de Krippendorff ≈ 0,88 e AC1 de Gwet ≈ 0,87. O alfa recebe o rótulo “confiável” (acima de 0,800), mas o intervalo dele vai de ≈ 0,58 a 1.

  3. Em palavras simples. O valor pontual parece ótimo, mas com 12 documentos a incerteza é grande: o alfa verdadeiro pode estar abaixo do mínimo aceitável de 0,667.

  4. Cuidado. O rótulo vem do valor pontual; a decisão deve olhar o intervalo. Krippendorff (2018, sec. 12.5) decide pela chance de o alfa estar abaixo do mínimo exigido, e aqui essa chance não é pequena. Com 12 documentos não dá para afirmar que a codificação é confiável: aumente a amostra (Neuendorf, 2017, sugere ao menos 50 unidades). O exemplo usa só 100 réplicas bootstrap para rodar rápido; em uso real, deixe o padrão de 1000.

6. Relatório de método: replicabilidade automática

Aqui está o coração desta vignette: ac_qual_report() empacota tudo (codebook, config LLM, distribuição de resultados, métricas de IRR) em um documento único, pronto para anexar como material suplementar de um artigo.

arquivo_md <- tempfile(pattern = "relatório-", fileext = ".md")

ac_qual_report(
  coded       = resultado,
  codebook    = cb,
  reliability = irr,
  chat        = "anthropic/claude-sonnet-4-5",  # ou objeto Chat
  title       = "Classificação de posicionamento na reforma tributária",
  author      = "Silva, A.; Souza, B.",
  method      = "Corpus de 12 pronunciamentos parlamentares (2023-2024).",
  format      = "md",
  path        = arquivo_md,
  lang        = "pt"
)

Fluxo completo em 6 linhas

Recapitulando toda a vignette em código executável:

library(acR); library(ellmer)
corpus    <- ac_corpus(meu_data_frame)
cb        <- ac_qual_codebook(name = "...", instructions = "...", categories = list(...))
resultado <- ac_qual_code(corpus, cb, chat = chat_anthropic("..."), live = "terminal")
amostra   <- ac_qual_sample(resultado, n = 30)   # aleatória: representativa
# ... revisao humana ...
irr       <- ac_qual_reliability(llm = resultado, human = revisado)
ac_qual_report(resultado, cb, reliability = irr, path = "metodo.md")

Seis funções principais, um pipeline reproduzível, um relatório automático: do texto bruto ao apêndice metodológico do artigo.
